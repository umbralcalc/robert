robert packages what a simulation scientist does as tools any coding agent can call. You ask a question; robert builds, tests and warrants a stochastic simulation to answer it, and every number in the answer traces back to a real run. 

curl -fsSL https://raw.githubusercontent.com/umbralcalc/robert/main/install.sh | sh

What it is

robert is the method layer of an AI simulation scientist. It leaves the simulation itself to stochadex, and adds everything a careful scientist does around it: stating the claim, building the model in parts with a hypothesis for each, fitting it to data, testing it, improving or simplifying it, and only then saying what it can be trusted for.

The agent does the implementation. You supply judgment where the work is new, and every point where you had to step in is logged. robert exists to test one claim: how far can simulation science be automated? The design doc has the full argument.

Questions become experiments

Each question is an experiment file holding the answer, its assumptions, its evidence and suggested follow-ups.

The agent never produces a number

Every figure comes from a stochadex run, with its config, seed and provenance recorded.

Gates, not templates

The MCP server checks each step before the next can start, so every agent is held to the same standard.

Answers argue against themselves

Every answer states the strongest case against it and lists every analysis that was tried.

Install

One line installs robert, the stochadex release it locks, and the agent integrations:

curl -fsSL https://raw.githubusercontent.com/umbralcalc/robert/main/install.sh | sh

The installer puts the robert-ai package in an isolated tool environment (using uv, then pipx, otherwise installing uv first) and runs robert setup, which:

  • downloads the locked stochadex release into ~/.robert/stochadex/<version>/ and checks its SHA-256;
  • installs the Claude Code plugin (skills and MCP server) if claude is on your PATH;
  • adds the MCP server to ~/.cursor/mcp.json if Cursor is installed.

Check the toolchain at any time with:

robert doctor
OptionEffect

In the cloud

The image ghcr.io/umbralcalc/robert:<version> contains robert, the locked stochadex, Python and git. Projects created by robert init open in it as a dev container or Codespace, and any other repo can add the feature ghcr.io/umbralcalc/robert/robert:0. See cloud/README.md for running robert as a cloud agent.

Use it

Most of the time you talk to your agent and it calls robert's tools for you. Every command is also an MCP tool with the same arguments, so a project driven through chat leaves the same trail as one driven by hand.

  1. Start a project. robert init creates the repo skeleton and interviews you about the domain. The project carries its own .mcp.json, AGENTS.md and dev container, so any agent opened in it finds the tools.
  2. Ask a question. Tell your agent what you want to know. It runs ask, which opens an experiment in experiments/E###.yaml.
  3. Let it work the loop. The agent builds and tests a model step by step (below). It asks you what you believe about the world only when the answer depends on it.
  4. Read the answer. answer records it once the gate is satisfied: assumptions, evidence, the strongest case against, and follow-up questions.
  5. Go deeper. Take up a follow-up with ask --from-follow-up E002.1. The chain of experiments becomes the context for the next question.
ToolDoes
askOpens an experiment for a question or a suggested follow-up
answerRecords the answer; the gate checks assumptions, evidence and follow-ups
contextWhat earlier experiments established, compressed; with --focus, a chain in full
standingThe questions every answer must report on: contradictions, surprises, operationalisation choices
status, explainWhere the project stands, and why

See it end to end

From a clone of the repository, the worked example runs the whole loop against real stochadex runs:

examples/logistic-growth/walkthrough.sh /tmp/logistic-demo

Unconstrained growth fails its backtest; the user redirects; discover adds a carrying capacity that beats its parent on held-out years; compress removes a seasonal nuisance without moving the claim; a forecast is warranted and queried; and a decide query is refused because nothing on the action path was tested.

The loop

This is how robert earns each answer. Each step writes a file, and a gate must pass before the next step can start.

pose→conjecture→confront→test→discover / compress→warrant→query→revise
StepGate before moving on
poseQuestion, claim, intended use and conditions named
conjectureThe config checks and runs reproducibly; each model part has a role and a hypothesis
confrontThe fit to data converged; weak identifiability flagged
testEvery structural part passed; a backtest ran
discoverA new variant beats its parent on held-out prediction
compressA smaller variant leaves the claim unchanged within tolerance
warrantThe current variant passed its tests; limits stated
queryThe warrant is strong enough for the kind of question asked
reviseMonitors watch the model and name their action

A failed test sends the agent to discover a better model. Learned (ONNX) components must earn their place there, after mechanistic variants have failed and you have approved.
